# Session protocol (playlist, voting, scoring)

Additions to the WS protocol for the party-session layer. Envelope format is unchanged: `{type, requestId?, roomId?, payload?}`; requests get `<type>.ok` / `<type>.error` replies, server pushes have no `requestId`.

## Room lifecycle

`room.status` (in every room snapshot): `lobby → playing → results → voting → lobby → …`

- **lobby** — ready-up. If `nextGameType` is set, that game is queued; otherwise the first `game.start` picks randomly from the playlist.
- **playing** — a game adapter is running; `gameType`/`gameName` describe it.
- **results** — last game finished; its standings were pushed via `session.gameResult`. Admin advances with `session.vote.start` (or `session.end` to end the night).
- **voting** — next-game vote is open.

## Changed requests

### room.create
New payload fields:
- `playlist: string[]` — game types for the night (≥1, all must be registered; duplicates are dropped, order kept). Back-compat: a lone `gameType` string still works and becomes a 1-game playlist.
- `password?: string` — optional room password.
- `locale?: string` — `"en"` (default) or `"pt-BR"`; used for game content.

`gameType`/`gameName` in snapshots are now the *currently running* game (empty in lobby).

### room.join
- `password?: string` — required when the room snapshot/public view has `hasPassword: true` (not needed on rejoin of an existing session).
- New error codes: `invalid_password`; `name_taken` when another player already uses the display name (case-insensitive). On a rejoin, a conflicting rename silently keeps the old name instead of blocking the reconnect.
- `rate_limited` — the caller's IP failed too many joins (unknown room/code, wrong password: burst 20, then ~1 per 5s). Successful joins/rejoins never count, so a household reconnecting behind one NAT is unaffected.
- `playerId` — `room.join.ok` and `room.create.ok` payloads are the room snapshot plus `playerId`, the caller's own seat id. Use it instead of matching your display name (the server may have suffixed it, see below).
- Capacity (`maxPlayers`), the name check and the insert are one atomic step, so concurrent joins can neither overfill a room (`room_full`) nor seat two players under one name (`name_taken`).
- **Embedded in awful.chat** — `awfulSession?: string` (≤128 chars, else `invalid_payload`): the host app session the Gemu tile was opened from. With no `roomId` (and no `joinCode`, or a code that no longer resolves) the server joins the room bound to that session, creating it on first open — everyone who opens the same app card lands in the same room, and the first opener is host. Creation payload fields used: `locale`, `playlist` (unknown games dropped; empty = every registered game), `roomName` (default `"Gemu"`). Such a room is private (not listed, still has a join code), has no password and seats up to 16; joining it via the session skips the code/password checks. Only a hash of the session id is kept (and persisted with the room). Display names coming from the host are labels, not unique: a taken name is suffixed (`"Ana"` → `"Ana 2"`, `"Ana 3"`…) instead of failing with `name_taken` — the reason `playerId` exists. Creating the room can fail with `rate_limited` / `server_full` like `room.create`.
- **Reconnect takeover**: a rejoin (same `sessionId`) into the room the session already sits in succeeds even if the old socket still looks alive. The old connection is unbound and gets a `room.sessionReplaced` push (`{reason: "session_replaced"}`); it stays open, so a client receiving it must NOT auto-rejoin (show "opened in another tab" instead) or two tabs would steal the seat back and forth. `session_in_room` now only means the session is live in a *different* room.
- Join codes are 6 characters from `23456789ABCDEFGHJKLMNPQRSTUVWXYZ` (no 0/O/1/I), crypto-random and unique among live rooms; matching is case-insensitive.

### room.kick (admin)
The target must be a member of the admin's own room (`not_found` otherwise); kicking yourself is `invalid_target` (use `room.leave`). Only the connection seated as that player in that room is unbound and gets `room.kicked`.

### game.start (admin)
Payload: `{force?: bool, settings?: {…}}`. Only valid in `lobby` status; starts `nextGameType` if set (from a vote, replay or `session.next.random`), else (back-compat) a random playlist game. The min-players check applies to a queued game too. Resets ready flags. `game.start.ok` payload: `{gameType, gameName}`. Error codes: `wrong_status`, `empty_playlist`, `not_enough_players` (payload includes `minPlayers`), plus the old ones.

**Game settings** (host options panel; all optional ints, server clamps to sane ranges):
- invention: `rounds` (1–5, default 3)
- stop: `rounds` (1–10, default 3), `answerSeconds` (30–300, default 90)
- gartic: `rounds` (1–10, default 2), `turnSeconds` (30–180, default 75)
- garticphone: `drawSeconds` (30–300, default 120)
- cah: `rounds` (3–20, default 8)
- trivia: `rounds` (1–20, default 8; also capped by the question pool), `answerSeconds` (10–60, default 20)
- fibber: `rounds` (1–10, default 4; also capped by the prompt pool), `writeSeconds` (20–120, default 45)

**Minimum players**: `lobby.games.list` entries now include `minPlayers` (garticphone, cah and fibber need 3, the rest 2). `game.start` enforces it, and the next-game vote only offers games the current group is big enough for (falling back to the full playlist if none qualify).

Every game needs at least 2 connected players to start; a game that is already over right after `Start` (e.g. Gartic when fewer than 2 players are connected) is finalised at once — `game.state`, `session.gameResult` and status `results` follow the `game.start.ok`.

### game.action
Unchanged, but errors with `no_active_game` between games. Unknown actions are an error (`bad_action`, message `unknown action`).

### game.state delivery
`game.state` is coalesced per room: the first broadcast after a quiet period, and any broadcast that changes the public `phase`/`round`/`turnIndex`/`deadline`, goes out at once; further state changes within ~120ms collapse into one trailing broadcast carrying the latest state (public + each seat's private view, read when it is sent). So a burst of reactions or guesses yields a couple of broadcasts, not one per action — clients must always render from the latest `game.state`, never count them. `game.action.ok` may arrive before the state it caused. The final state of a game is always sent immediately, before `session.gameResult`.

### game.stream (new)
High-frequency transient channel for canvas strokes. Client sends `{type: "game.stream", payload: {action: "stroke" | "canvas_clear" | "canvas_undo", ...opaque stroke data}}`. The `action` MUST be one of that allowlist — the hub rejects anything else outright (so a non-drawer can't route real game actions or arbitrary keys through the relay). For an allowlisted action the server still consults the game (e.g. Gartic accepts strokes only from the current drawer during the drawing phase), then relays the payload verbatim — plus `playerId` — to everyone else in the room as a `game.stream` push. No full-state broadcast, no ok/error replies (illegal streams are dropped silently). Rejected while the room is paused. Strokes are not persisted server-side: a reconnecting player gets a blank canvas mid-turn.

### Limits & validation
The server caps client input to keep broadcasts bounded: display name ≤40 chars, room name ≤60, password ≤100, avatar/data URL ≤256KB, guess/answer/title text truncated per game, `maxPlayers` clamped to 2–16.

**Drawings** (invention, gartic phone — anything stored and rebroadcast in game state) must be base64 `data:image/png|jpeg|webp` URLs of at most **200,000 bytes** (`games.ValidImageDataURL`). Clients should export compressed JPEG/WebP (≈150KB or less); a full-size PNG will be refused.

**Rate limits** (per connection): `game.stream` 60 msgs/s (burst 120, excess dropped silently); every other message type 20 msgs/s (burst 40) — over that the server replies `system.error {code: "rate_limited"}` with the request's `requestId`. Plus per-IP limits on new connections, room creation and failed joins.

**Slow clients**: each connection has a bounded outbound queue (256 messages / 32MB) drained by its own writer with a 10s write deadline. A client that stops reading is disconnected (normal reconnect path) rather than stalling the room. A connection already bound to a room must `room.leave` before creating/joining another (`already_in_room` error). A rejoining client during `voting` is re-sent the open `session.vote` + counts.

## New requests

- `session.playlist.set` `{playlist: string[]}` — admin, in `lobby`/`results`. Replaces the playlist (≥1 registered games, duplicates dropped). If the queued `nextGameType` is removed, it is cleared.
- `session.next.random` — admin, in `lobby` with no `nextGameType` queued (else `wrong_status`). Picks a random playlist game the connected group is big enough for (falling back to the whole playlist, like the vote), queues it (`nextGameType`/`nextGameName`, ready flags cleared, status stays `lobby`), replies `session.next.random.ok {gameType, gameName}`, and broadcasts `session.vote.result {gameType, gameName, counts: {}}` then `room.updated` — so the first game gets the same drumroll → intro flow as a voted one. Errors: `not_admin`, `wrong_status`, `empty_playlist`.
- `session.vote.start` — admin, in `results`. Opens the next-game vote. If the playlist has ≤1 game there is nothing to vote on: the room goes straight to `lobby` with `nextGameType` queued.
- `session.replay` — admin, in `results`. "Same again": queues the game that just finished (status → `lobby` with `nextGameType` set, ready flags cleared) instead of voting. Each play is scored as its own game in the session.
- `session.vote.cast` `{gameType}` — any player, in `voting`. One vote per player, revotable until resolved. The vote closes early once every *connected* member has voted (re-checked when someone disconnects or leaves); a player who leaves the room loses their ballot, a disconnected player's ballot still counts in the tally. Errors: `no_vote_active`, `invalid_option`.
- `session.end` — admin, any status except `playing`. Pushes the final podium then resets scores/history to a fresh lobby.

## Live in-game scoreboard

Every `game.state` broadcast — and the one sent to a (re)joining player — carries `standings: [{playerId, score}]` (best first, game-native running totals, limited to current room members) alongside `public` — render the persistent "who's winning" scoreboard from this one field for every game instead of digging into per-game keys like `wins`/`totalScores`/`scores`.

## New pushes

- `session.gameResult` `{gameType, gameName, standings: PlacementRow[]}` — after a game finishes. Also implies status → `results` (see the `room.updated` that follows).
- `session.vote` `{options: [{type, name}], deadline: epochMillis}` — vote opened; up to 5 options sampled from the playlist, 30s window.
- `session.vote.update` `{counts: {gameType: n}}` — live tally after each cast.
- `session.vote.result` `{gameType, gameName, counts}` — winner (most votes; tie → random). Status → `lobby` with `nextGameType` set and ready flags cleared.
- `session.final` `{standings: PlacementRow[], playedGames: PlayedGame[]}` — final podium for the night.

`PlacementRow = {playerId, name, place, score, points}` — `score` is game-native (raw), `points` are session points: place 1→100, 2→75, 3→60, 4→50, then −5 per place (floor 10). Tied raw scores share a place and its points. Rows only include current room members (connected or not) — players who left are dropped and places recomputed; `name` is captured when the row is built, so `playedGames` history keeps names of people who left later.

`PlayedGame = {gameType, gameName, standings: PlacementRow[]}`

## Room snapshot additions

`status`, `playlist`, `nextGameType`, `nextGameName`, `sessionScores: {playerId: points}`, `playedGames`, `hasPassword`, `locale`. Public room list entries add `hasPassword`, `status`, `playlist`.

## Implemented games

- **invention** ("Patently Silly") — phases `collecting (90s) → drawing (180s) → presenting (45s per pitch) → voting (60s) → results (20s, then next round) → finalResults`; standings = total funding. Every phase has a timer (public `deadline`) and the admin can `{action:"advance", phase?, round?}` any phase — when `phase`/`round` are sent and no longer match (a double-click racing a timer), the advance is ignored. Gates count only CONNECTED players: collecting waits for 2 problems each (`{action:"submit_problems", problems:[...]}`), drawing waits for players who were assigned a problem (late joiners get a fallback problem and may still draw), voting waits for players who have someone to fund. Public `doneCount`/`neededCount` show progress. Drawing: `{action:"submit_drawing", title, tagline, draw}` (`draw` must pass `ValidImageDataURL`); `drawing` appears in private state only once submitted. Presenting: the presenter or the admin sends `{action:"next", presentIndex?, presenter?}` (stale tags are ignored the same way); during presenting, other players' submissions arrive without `dataURL` — only the current presenter's drawing is included (voting and results carry all drawings); disconnected presenters are skipped; `{action:"react", kind:"fund"|"trash"|"rocket"}` toggles one reaction per kind per player per pitch (not your own), counts in public `reactions`. Voting: `{action:"fund", funding:{playerId: amount}}` — each amount 0..1000, total ≤ 1000, empty allowed. Unknown actions return an error.
- **gartic** ("Gartic") — phases `drawing → turnResults`, rotating drawer, `rounds` rounds (everyone connected draws once per round; a new player can guess at once and draws from the next round), `turnSeconds` turns, 6s reveal. Public state: `drawer`, `turnOrder`, `turnIndex`, `round`/`totalRounds`, `deadline` (ms; turn end while drawing, reveal end in `turnResults`), `turnStartedAt` (ms) + `turnSeconds` (late joiners sync their canvas/timer bar off them), `scores`, `guessed` (ids in guess order), `guesses` chat (last 30). While drawing: `mask` (the word with unrevealed letters as `_`, spaces/hyphens kept, e.g. `"______ __ ____"`), `letters` (letter count), `nextHintAt` (ms, when another letter is revealed: one at half time for words ≥4 letters, a second at ¾ for ≥6; the last two hidden letters are never revealed), `graceEnd` (ms, only while the turn is unplayable — see below). `word` replaces `mask` in `turnResults` and after the game. Guess lines are `{seq, playerId, text, correct, close?, points?}`: a wrong guess carries its `text`; a correct one carries `points` and no text; a near miss has `close: true` and no text (render "<name> is close!"). Private: the drawer gets `word`; a guesser gets `closeGuess` (their latest near miss) and `ownClose` (`{"<seq>": text}`) so they see their own hidden lines. Actions: `{action:"guess", text}` (≤80 chars) via `game.action`; strokes via `game.stream` (drawer only, drawing phase only). Matching: both sides are normalized — lowercase, accents stripped, only letters/digits kept (so "Arco-Íris", "arco iris", "ARCOIRIS!" match) — and a simple plural/singular in either direction counts (en `s`/`es`/`y→ies`; pt-BR `ão→ões/ães/ãos`, `l→is`, `il→is/eis`, `m→ns`). Close = edit distance ≤2 (≤1 for words of ≤5 letters), or containing the word, or a ≥3-letter chunk of it. Scoring: 1st correct guess 100, then −10 each (floor 50); drawer +25 per correct guesser. Everyone guessed → the turn ends early. A disconnected drawer (or nobody left to guess) starts a 10s grace (`graceEnd`) instead of ending the turn — a refresh comes back within it; the drawer *leaving* ends the turn at once. A 2-player game whose second player drops at the turn boundary waits once (10s) before ending; fewer than 2 connected players ends the game.
- **stop** ("Stop!") — phases `answering → validating → roundResults`, `rounds` rounds of a letter + 8 categories. Answers via `{action:"set_answers", answers:{category: text}}` (≤60 chars each, accepted through the STOP grace), early stop via `{action:"stop"}` (only with every category filled, else an error; cuts everyone else to a 5s grace), validity votes: per answer `{action:"vote", key:"category|playerId", valid: bool}` (revotable until you lock) and lock-in `{action:"validate", rejected?:["category|playerId"]}` (optional bulk list; anything left unjudged counts as valid). Only players who took part in the round vote, never on their own answers; answers not starting with the letter are auto-invalid and not voted on. Validating public state: `answers` (`category → [{playerId, answer, autoInvalid}]`), `tally` (`"category|playerId" → {valid, nope}` live counts), `validatedCount`/`requiredCount` (connected participants with something to judge); the phase ends when all of them locked or after 60s. A strict majority of `nope` among voters rejects an answer. `roundResults` public: `results` (`category → [{playerId, answer, verdict: unique|duplicate|invalid, points}]`), `roundScores`, `final` (last round). Admin `{action:"next_round"}` advances between rounds; after the final round the results stay up for 10s (`deadline`) and then the game finishes on its own. Private: `round`, own `answers`, `validated`, `votes` (`key → "valid"|"nonsense"`), `rejected`, `judge` (whether you vote). Public `answering` extras: `stopped`/`stoppedBy`, `answersFilled` (count per player), `remainingMs` (skew-free countdown).

`remainingMs` (Gartic Phone work phases, Stop answering) is the milliseconds left when the message was *built*; coalesced broadcasts build state at send time, so it stays fresh — anchor it to the local clock on receipt. Scoring: unique valid 10, duplicate 5, invalid 0; standings = `totalScores`.

- **garticphone** ("Gartic Phone") — phases `prompt → drawing → writing → … → reveal`. Everyone writes a prompt (60s); chains rotate each step, alternating draw-the-text (120s) and describe-the-drawing (60s) until each chain passed through every player; missed submissions are autofilled ("…" / blank drawing). Public `round`/`totalRounds` are the 1-based step (work phases) or chain (reveal). Reveal is admin-paced: `revealChain` is the chain on screen (all earlier chains are fully shown) and `revealPos` is the COUNT of its revealed entries (1..len; the newest is `entries[revealPos-1]`). The reveal opens at `revealChain=0, revealPos=1`. `{action:"reveal_next", chain?, pos?}` (the optional cursor the client saw; ignored if stale, so a double-press can't skip an entry) shows the next entry, or opens the next chain once the current one is fully shown; `revealDone: true` means the last chain is fully shown and the next press ends the game (N entries = N presses). `chains[i]` is `{starter, length, entries}`; during the reveal (and once finished) only `chains[revealChain].entries` is filled (masked to the revealed prefix) — other chains carry `starter` + `length` with empty `entries`, to keep broadcasts small. Work phases (`prompt`/`drawing`/`writing`) also carry `remainingMs`. During the reveal anyone can `{action:"react", chain, entry, emoji}` (emoji 😂/💀/⭐, anything else stored as ⭐) — one reaction per player per revealed entry, not on your own entries, +10 to the entry's author; reactions are the score. Work-phase submissions: `{action:"submit_prompt"|"submit_description", text}` and `{action:"submit_drawing", draw: dataURL}` (png/jpeg/webp data URL ≤200KB, else an error). Private state carries the player's `prevEntry` to draw/describe, `myReactions` (`"chain|entry" → emoji`) and `spectator: true` for players who joined after the start.

- **cah** ("Cartas") — phases `answering (75s) → judging (60s) → roundResults (8s, auto)`, `rounds` rounds, rotating judge, hand of 5. Answering: non-judges `{action:"submit", cards:[handIndex,...]}` (exactly `blackCard.pick` distinct indices; locked once submitted). Public `submitted` (ids), `submittedCount` and `expectedCount` (connected non-judges able to play — the round waits only on them). Judging: anonymized shuffled `submissions`; judge `{action:"pick_winner", index}` (not their own); judge timeout, or a judge who disconnects/leaves, → random winner right away. An answering timer with no submissions skips the round. Round results `reveal` (`[{playerId, cards, winner}]`) + `winner`. Raw score = round wins (`wins`). Private: `hand`, `isJudge`, `submitted`, `played`. Players who join mid-game are dealt in at once and enter the judge rotation. The selected decks are merged and de-duplicated, topped up from the locale's base deck when too small for the table, and discards are recycled. Built-in decks are embedded JSON in `server/internal/games/decks/` — `base_en.json`, `base_pt-BR.json`, `party_en.json`, `nsfw_en.json`, `nsfw_pt-BR.json` — format `{id, name, locale, nsfw?, black:[{text,pick}], white:[...]}` (original content, not real CAH text). See *CAH decks* below for custom decks.

- **trivia** ("Trivia") — phases `question → reveal` per round, `rounds` questions (multiple choice, 4 options, locale question bank), `answerSeconds` to answer, 6s reveal, then the next question; finished after the last. Action: `{action:"answer", choice: optionIndex}` — one answer per question, locked; late answers after the reveal are ignored, an out-of-range index is an error. The question ends early once every connected player answered. Public: `phase`, `round`/`totalRounds`, `question`, `options`, `scores`, `answered` (ids in answer order), `deadline`; on `reveal` also `correct` (index), `choices` (`playerId → index`) and `gained` (`playerId → points` this question). Private: `round` (to tell a fresh private payload from the previous question's) and `choice` once answered. Scoring: correct = 100 + speed bonus by order among correct answers (+50, +40, … +0).

- **fibber** ("Fibber", min 3 players) — per round `writing → choosing (30s) → reveal (8s)`, `rounds` rounds of a fill-in-the-blank fact. Writing (`writeSeconds`): `{action:"lie", lie: text}` (≤80 chars; one per round). A lie that matches the truth or another player's lie (case/accents/spacing/punctuation-insensitive, leading article ignored) — or has no letters/digits — is not recorded: it comes back in the author's private `rejected: {text, reason: "truth"|"duplicate"|"empty"}` and they write another. Choosing: `{action:"choose", choice: optionIndex}` (one pick, not your own lie). Phases end early once every connected player wrote / picked. Public: `phase`, `round`/`totalRounds`, `prompt`, `scores`, `deadline`; writing `written` (ids); choosing `options` (texts only — no authors) + `picked` (ids); reveal `options` (`[{text, author, truth}]`), `picks` (`playerId → index`), `answer`, `gained` (`playerId → points`). Private: `round`, `phase` (trust a private payload only once it matches the public phase), own `lie`, `rejected` (writing only), `choice`, `ownOption` (choosing: index of your own lie, to grey it out). Scoring: +100 for picking the truth, +50 to a liar per player fooled.

## For game implementers (backend)

Games implement `games.Adapter` (`server/internal/games/adapter.go`): a self-driving state machine. Advance phases inside `OnAction`/`OnTimer`/`OnRoomChange` (roster via `Options.Room.ConnectedPlayerIDs()`), report a single pending countdown via `NextDeadline()` (the hub re-arms it after every call and calls `OnTimer(name)` when it fires), flip `Status()` to finished and expose `Standings()` when done. `OnTimer` must leave the next deadline in the future (or report none): if the same timer comes back already overdue, the hub logs it once and re-fires it only after a 1s backoff instead of spinning. Unknown actions must return an error. Keep `PublicState` small — it is rebroadcast (coalesced, ≤ ~8/s) to every player. The hub handles everything else: scoring, results, votes. No hub changes needed to add a game — register a `Factory` in `cmd/server/main.go` and add the frontend component in `web/components/GameSurface.tsx`.

## Pause (host)

- `session.pause` — admin, `playing` status only. Freezes the show: the pending game timer stops, `game.action`/`game.stream` are rejected (`paused`) until resume, and the room snapshot carries `paused: true` (render the pause overlay from it).
- `session.resume` — admin. Shifts every pending game deadline forward by the frozen duration (games implement `Shift`), re-arms the timer, and re-broadcasts `game.state` so client countdowns pick up the shifted deadline.
- While paused, joins, leaves and disconnects are queued instead of reaching the game (`OnPlayerJoin`/`OnPlayerLeave`/`OnRoomChange` could otherwise advance a phase whose new deadline resume would push out by the whole pause). On resume they are replayed after `Shift` (joins, then leaves; someone who joined and left within the same pause is dropped from both). A player joining mid-pause is seated normally and still receives the current `game.state` (public, private, standings).
- A game that finishes (or a room that is removed) while paused never leaves the next game paused.

## CAH decks

- `lobby.decks.list` → `lobby.decks.list.ok {decks: [{id,name,locale,nsfw,black,white}]}` — decks the room can pick (built-in ∪ this room's custom uploads). Fetched on room entry.
- `session.cahdecks.set {decks: [id,...]}` — admin. Records which decks CAH shuffles together (invalid ids dropped; empty = the locale's base deck). Selection is on `room.cahDeckIds` in the snapshot.
- `session.deck.add {deck: {name, locale?, nsfw?, black:[{text,pick}], white:[]}}` — admin. Validates + stores a custom deck for the room, auto-selects it. Its id is `custom:<slug>-<8hex>` — a readable slug of the name (lowercase letters/digits, other runs → `_`, ≤32 chars) plus the first 4 bytes of the SHA-256 of the whitespace-normalized name — so it never shadows a built-in and distinct names never collide. Limits (hub + `games.ParseDeck`): name required, ≤60 chars (truncated by the hub), each card ≤200 chars and non-empty, ≤1000 cards total, ≥1 black and ≥10 distinct white cards (duplicates are dropped case-insensitively, whitespace collapsed, runs of 3+ `_` normalized to one blank), locale defaults to `en`; ≤20 custom decks per room; re-uploading a deck with the same name replaces it (even at the cap). Custom decks are persisted with the room. Errors: `invalid_deck` (message carries the reason), `too_many_decks`.
- `session.cahdecks.set` ids are deduped and capped at 40. Deck format: black cards are `{text, pick}` where `pick` ∈ {1,2}; a question card (no `____`) is pick 1, a fill-in has `pick` blanks. A missing/0 `pick` is inferred from the blanks. Built-in deck ids: `base_en`, `base_pt-BR`, `party_en`, `nsfw_en`, `nsfw_pt-BR` (files of the same name under `server/internal/games/decks/`).
